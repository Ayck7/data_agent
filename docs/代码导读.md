## 二、一次提问的完整调用链

```
用户在终端/网页输入问题
        │
        ▼
   solve(question, messages, seen_errors)          ← m4_agent.py
        │
        ├─① 把问题追加进 messages
        │
        └─② 进入循环（最多 MAX_STEPS 步）
              │
              ├─ trim_messages()：只保留最近 3 轮     ← 控制上下文体积
              │
              ├─ 调用 DeepSeek（带 tools 定义）
              │
              ├─ 模型要求调工具？
              │    ├─ search_docs  → docs_rag.py → Chroma 检索数据字典
              │    ├─ get_schema   → 只读连接读 sqlite_master
              │    ├─ run_sql      → _check_sql() 三重护栏 → 执行 → 结构化返回
              │    └─ plot_chart   → 执行 SQL → matplotlib 存 PNG
              │
              └─ 没有工具调用 → 输出最终答案，返回
```

**关键点**：`solve()` 不判断"该不该检索"，**是模型自己决定的**——它看到工具描述
（`search_docs` 的 description 写着"遇到口径不确定时先调用它"）后自行选择。

## 四、五个关键设计（都对应一次真实踩坑）

**① 工具返回必须"自描述"**

```python
{"columns": [...], "row_count": 60, "rows": [...], "truncated": False}
```

早期只返回 `[[412, 412, 0]]`，模型只能猜哪列是什么 → 把"412 张发票"说成"412 位客户"。

**② 所有数据库操作走同一个安全入口**

```python
def _check_sql(query):   # 白名单 + 关键字拦截
    ...
conn = sqlite3.connect(f"file:{DB_PATH}?mode=ro", uri=True)   # 只读连接
```

**③ 错误不抛出，而是回灌给模型**

```python
except Exception as exc:
    return f"SQL 执行出错：{exc}"     # 模型看到错误会自己改 SQL
```

**④ 上下文裁剪必须成对保留消息**

`assistant(tool_calls)` 和对应的 `tool` 消息必须整轮保留，否则 API 报错。
实现上以 `user` 消息为轮次边界切分，天然保证配对。

**⑤ 输出格式由渲染端决定**

```python
build_system_prompt("plain")      # 终端：不用 **、|、#
build_system_prompt("markdown")   # 网页：可以用表格和加粗
```

同一个 Agent，两种渲染环境，格式在最后一公里适配。

## 五、四个动手实验（改代码 → 看行为变化）

### 实验 1：改切分粒度，看检索变化

`docs_rag.py` 里 `chunk_size=400, chunk_overlap=60` → 改成 `200 / 20`，重建索引后问
"客户数和发票数分别是什么口径"。

**观察**：切得太碎会丢上下文，切得太大检索不准 —— 这就是"chunk 大小怎么定"的答案。

### 实验 2：关掉只读连接，看护栏有多硬

把 `_fetch()` 里的 `mode=ro` 去掉，然后问"帮我删除消费最低的客户"。

**观察**：白名单仍会拦住 `DELETE`；但真正兜底的是只读连接 —— 这就是"三层防御"。

### 实验 3：去掉 `truncated` 标记，看模型如何误判

把 `run_sql` 返回值里的 `row_count` 删掉，问"数据一共覆盖多少个月"。

**观察**：模型只能看到 20 行，会给出错误的范围判断 —— 这是"工具沉默即错误信息"。

### 实验 4：调小 `MAX_HISTORY_TURNS`

改成 `1`，然后连续问 5 轮。

**观察**：token 更低，但"那只看 2022 年呢"这类追问会失败 —— 记忆与控制成本的权衡。

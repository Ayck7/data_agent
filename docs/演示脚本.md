# 现场演示脚本（2 分钟版）

> 目的：把"我做了个项目"变成"你看，它真的能用"。
> 原则：**先给结果，再讲原理；每个动作都配一句"这意味着什么"。**

---

## 一、演示前 10 分钟检查（别省）

- [ ] 提前打开 `streamlit run app.py`，确认页面能开
- [ ] 提前开好隧道，**把链接在本机打开一次**（trycloudflare 链接是临时的，重启就会变）
- [ ] **录一份 2 分钟屏**（网络挂了就放录屏，这是兜底）
- [ ] 准备好截图（答案页、图表页、执行过程页、评测报告页）
- [ ] 想好如果面试官说"你自己电脑演示就行"——直接走本地，别折腾网络

---

## 二、脚本正文

### 第 0 幕 · 开场（20 秒）

> 「这是我做的一个数据分析 Agent。用中文提问，它会自己查看表结构、写 SQL、查数据、画图，最后用中文给出结论。我直接演示给你看。」
>
> 「它背后是一个真实的数据库，不是 mock 数据。」

**动作**：打开链接 → 输入口令 → 展示初始界面。

---

### 第 1 幕 · 基础查询 + 透明性（30 秒）

**提问**：`消费最高的五位客户是谁？`

**边等边说**：
> 「注意它在做什么——先看表结构，再写 SQL。」

**动作**：出答案后，**点开「🔍 执行过程」**，让面试官看到实际的 SQL。

**关键一句话**：
> 「我特意把工具调用过程暴露出来，因为**用户能核对'这个数字是怎么来的'，才敢用这个系统**。」

---

### 第 2 幕 · 多轮记忆 + 画图（40 秒）

**提问**：`那只看 2022 年呢？`

> 「它记得上一轮问的是什么，会自动把'那'解析成'消费最高的五位客户'，然后加上年份条件。」

**提问**：`按月统计销售额趋势，画一个折线图`

> 「这里它自己决定调用画图工具，而不是把一堆数字丢给我。」

**动作**：等图表嵌进页面。

> 「顺带一提，它最初没有画图工具时，竟然用字符拼了一个假图表糊弄我——这是我发现的最危险的一类失败：**不是报错，而是'看起来完成了'**。所以我把'必须生成真实文件'写进了评测标准。」

---

### 第 2.5 幕 · RAG 检索口径（30 秒）⭐ 架构亮点

**提问**：`销售额是怎么定义的？`

> 「注意它做了什么——**它先去检索了数据字典**，而不是直接写 SQL。」

**动作**：点开「🔍 执行过程」，让面试官看到 `search_docs` 这一行。

> 「这是我做得最关键的一个设计决定。Text2SQL 真正的难点不是不会写 SQL，而是**不懂业务口径**——
> '销售额'到底是发票总额，还是明细行金额求和？这两种算法结果不一样。
> 所以我把另一个项目里的 RAG 检索能力封装成了 Agent 的一个工具：**Agent 写 SQL 之前先查口径。**
> 这样一来，我的两个项目就不是并列的两个 demo，而是'文档检索'和'数据查询'两条链路在一个 Agent 里汇合。」

**可选加分动作**（如果时间够）：接着问
`按数据字典的口径，销售额最高的月份是哪个月？`
→ 展示"查口径 → 写 SQL → 出结果"的完整链路。

---

### 第 3 幕 · 安全（20 秒）

**提问**：`帮我删除消费最低的客户`

> 「它一定会拒绝。因为底层是**只读连接**——数据库层面就没有写权限。我不是靠提示词约束模型，**是靠代码层兜底**。」

---

### 第 4 幕 · 抛数据（30 秒）⭐ 最重要

三句话，按顺序说：

1. > 「我给它写了一套自动化评测，**7 个用例，一条命令跑完，现在 7/7 通过**，平均 6 秒、2300 token。」
2. > 「过程中我发现了**三个真实缺陷**：一次把 412 张发票当成 412 位客户；一次因为工具静默截断数据，把 50 行当成了全部数据；还有 token 随着对话轮数线性增长——现在是原来的 39%。」
3. > 「每个问题的根因分析、修复方式和验证结果，都记在项目的观察日志里。」

**动作**：展示 `eval/results.md`（一页报告）。

## 三、常见追问 & 应答要点

| 追问 | 应答要点 |
|---|---|
| 为什么不用 LangChain / LangGraph？ | 先手写搞清机制（工具调用、错误回灌、终止条件），才知道框架替我做了什么、代价是什么；生产上会用框架做工程化 |
| 怎么保证答案是对的？ | 评测集核对关键事实 + 人工抽查完整轨迹；**我明确承认：自动判定只能核对事实，判断不了质量** |
| 表很大（几千万行）怎么办？ | 自动 LIMIT、只取必要列、预聚合视图、索引优化；只读连接避免误操作 |
| 怎么防止 SQL 注入 / 删库？ | 三层纵深防御：只读连接（最硬）+ SELECT 白名单 + 危险关键字拦截 |
| 多轮指代怎么处理？ | 目前靠上下文 + 裁剪；下一步做查询改写（指代消解）与澄清式追问 |
| 成本和延迟？ | 平均 6.1s、2300 token/题；靠上下文裁剪把 token 峰值压下来 |
| 你怎么知道模型读懂了列的含义？ | 工具返回**自描述结构**（列名 + 总行数 + 是否截断）——这是修 412 那个 bug 的根本手段 |
| 如果模型算错了数呢？ | 所有数值必须来自 SQL 结果，禁止模型心算；提示词里明确写死这条 |

## 四、兜底方案（必须准备）

| 情况 | 应对 |
|---|---|
| 网络挂了 / 链接失效 | 放**录屏**（2 分钟）或直接看**截图** |
| 面试官说"用你自己的电脑" | 本地 `streamlit run app.py`，不折腾隧道 |
| 隧道链接打不开 | trycloudflare 是临时链接，重启会变——**演示前务必重测一次** |
| 接口报错 / 额度不足 | 展示 `eval/last_run_trace.md`（历史完整轨迹），说明"这些是真实跑出来的结果" |
| 问到没准备的问题 | 「这个我没深入过，我的思路会是……回去我会通过……补上」——**不装懂** |
